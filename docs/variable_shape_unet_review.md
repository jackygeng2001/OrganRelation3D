# 可变完整输入尺寸与 U-Net 尺寸对齐研究

日期：2026-09-23。状态：工程可行性研究，未实现网络、未运行 GPU；不冻结骨干、输入尺寸、spacing 或 padding 语义。

## 结论

完整 CT 重采样后的空间尺寸不必天然是 16 或 32 的倍数。可以让编码器保留各级真实 shape，解码时显式对齐对应 skip 的尺寸，并让最终输出及粗分支监督恢复到本次输入的 `(D,H,W)`。这是减少显式输入 padding 的可行方向，不保证所有奇数尺寸都能在任意 U-Net 配置下运行，也不证明 24GB 显存足够。

本项目仍在最深层完整特征网格上构建 15 个节点，不裁掉扫描两端、不局部建图、不新增有效区域 mask。

## 尺寸机制及可行路径

| 位置 | 可行处理 | 必须核查的条件 |
|---|---|---|
| 同尺度卷积 | 例如奇数卷积核、stride 1 和匹配的内部 padding 保持当前 shape | 具体卷积块、边界模式和归一化仍属待记录骨干配置 |
| 下采样 | 逐轴按实际 kernel、stride、padding、dilation 推导尺寸，保存各级 skip shape | 不假定每级恰好减半；检查尾部覆盖、采样中心及最小合法尺度 |
| 解码上采样 | 按对应 skip 的实际 `(Dk,Hk,Wk)` 指定输出 size，再融合 | 不仅检查拼接合法，还需检查各级坐标相位和边界行为 |
| 最终分割 | 恢复本次输入 shape，不裁剪原输入/标签来迎合输出 | 输出标签网格与输入 CT 网格完全一致 |
| 粗分支监督 | 按 METHOD_SPEC 将粗 logits 三线性上采样到输入 shape，再 softmax | 不能下采样标签或先 softmax 后插值替代 |

PyTorch 的 5D `interpolate` 支持 `trilinear` 和显式三轴 `size`；因此可指定 skip shape，而不是总使用 `scale_factor=2`。`align_corners` 会改变插值坐标，必须显式记录并在各相关路径中核对；相同 shape 本身不能证明解剖对应关系正确。来源：[PyTorch 2.8 interpolate](https://docs.pytorch.org/docs/2.8/generated/torch.nn.functional.interpolate.html)。

按官方 Conv3d 定义，单轴输出长度为：

```text
n_out = floor((n + 2*p - dilation*(kernel-1) - 1)/stride + 1)
```

例如 `kernel=3,stride=2,padding=1,dilation=1` 得到 `ceil(n/2)`；stride 1 时可维持原长度。这里是说明可行尺寸行为，不是在选定正式下采样。`padding='same'` 不支持 stride 大于 1，不能将该字符串当作所有下采样的通用解法。来源：[PyTorch 2.11 Conv3d](https://docs.pytorch.org/docs/2.11/generated/torch.nn.Conv3d.html)。

`kernel=2,stride=2,padding=0` 的 floor 池化得到 `floor(n/2)`，奇数长度的最后一个特征位置不在该池化层的窗口内；前置卷积可能已传播它的信息，不能因此等同于裁掉原始 CT，但仍应检查边界路径。`ceil_mode=True` 会改变输出尺寸及末端窗口，不能为了“能拼接”静默切换。来源：[PyTorch 2.8 MaxPool3d](https://docs.pytorch.org/docs/2.8/generated/torch.nn.MaxPool3d.html)。

举例：轴长 85，四次上述 floor 池化产生 `85→42→21→10→5`；单纯连续乘二不能回到所有 skip 尺寸。按已记录尺寸逐级恢复可解决 shape 不一致，但不会补回下采样丢失的信息。该例是公式推导，没有运行网络。

如后续骨干选择转置卷积，需要按目标 skip 尺寸处理可达的输出形状及 `output_padding`。它用于消解 stride 引起的输出形状歧义，并不是在输出尾部真正补零；转置卷积也不是卷积的数值逆变换。不能用一次固定 `output_padding` 宣称支持所有奇偶组合。来源：[PyTorch 2.8 ConvTranspose3d](https://docs.pytorch.org/docs/2.8/generated/torch.nn.ConvTranspose3d.html)。

## 三种“边界处理”不能混淆

1. **重采样网格边界**：整数网格为覆盖原扫描体素支持范围而有少量外扩，属于物理采样网格定义，必须记录 affine、中心、覆盖范围和边界取值。本轮重采样保真度报告应单独说明。
2. **模型输入显式补齐**：在已定义输入网格外添加额外体素以满足某个倍数，会改变进入编码器的范围，并可能改变深层 `N`、归一化坐标、相对大小和损失域。此项未获定义，不自行实施。
3. **卷积/池化内部边界规则**：规定特征算子在边界如何取值，不等于新增具有物理仿射的输入 CT 体素域；但会影响边缘响应、深层 shape 及感受野，仍是必须记录和测试的骨干行为，不能宣称完全无影响。

按实际特征网格构造 `u_a=x_a/max(n_a-1,1)`、`N=Df*Hf*Wf`，不额外平移坐标、不用原扫描 offset 替代、不排除某些特征位置。不同合法输入尺寸对应不同深层 shape 是当前公式允许的情况；网络结构选定后不能随病例临时改变下采样层数或步幅。

## 限制与后续验收

- 必须预先推导所有候选病例在每一级的 shape。上述无 padding 的 `kernel=2,stride=2` 连续 L 次时，各输入轴至少需达到 `2^L` 才能使该链输出非零；实际最小输入还受其他卷积、归一化和边界模式约束，不能只套此下界。
- 部分归一化配置在训练时不允许每个统计组只剩一个值。最深层轴长为 1 虽然节点坐标公式有定义，也不表示整个骨干合法或有足够空间表达力。
- `size` 对齐只解决输出数量。后续用空间斜坡、边界脉冲、奇偶混合尺寸检查编码/解码坐标相位，禁止用裁去末端 skip 来掩盖偏移。此特征对齐与 NIfTI 世界坐标重采样是不同层次的测试。
- 第一轮完整网络测试可逐例 batch 1，从而避免为了把不同尺寸堆入同一 batch 而补齐；这不冻结正式 batch，也不把梯度累积声称为所有归一化行为都等价。
- 可变输入减少了补齐体素，但激活、skip、双损失及反向仍可能超显存；后续必须在 AMD 主设备测完整网络。ROCm 与 CUDA 的数值/梯度兼容需要各自测试，不由 API 文档保证。
- 准备 CPU shape/梯度测试：200 例候选 shape 的纯尺寸推导、各轴奇偶组合、合法最小尺寸、比下界更小的清晰拒绝、最终/粗分支 shape、标签不进入前向、节点统计域未添加 mask。尚未执行这些网络测试。

工程可以继续研究尺寸推导、按 skip size 对齐和显式配置，而不修改既定关系公式。若必须改变统计域（输入补齐或有效域 mask）、裁扫描范围、调整固定坐标公式或以局部图替代完整图，必须先报告并取得用户确认。正式骨干的层数、步幅、归一化和插值约定仍需在实验配置冻结时统一记录；本文未替用户选定这些参数。
